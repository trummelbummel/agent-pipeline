<objective>
Close SR-012 from `.gsd/review_backlog.md` with a deterministic, coverage-gated CI fast lane that runs ahead of the expensive Python matrix, plus an explicit opt-in integration lane.

Purpose: CI currently runs `pytest tests` on five Python versions with no gate in front. That run collects the integration tests, which depend on provisioned inputs (untracked data/raw and a local Ollama) that GitHub runners don't have. The tox run passes `--cov` flags, but pytest-cov isn't installed, so coverage never actually runs. After this plan, one command (`make test`) is the fast lane locally and in CI. It covers import smoke, unit tests and a real branch-coverage floor. Integration tests are deselected everywhere by default and only run on explicit request.

Output: one commit `ci(SR-012): ...` touching pyproject.toml, uv.lock, Makefile, tox.ini, .github/workflows/main.yml and README.md, plus a local resolution note in the gitignored backlog.

Planner decisions (Claude's discretion; no CONTEXT.md exists for this quick task):
- P-01: The integration default-deselection lives once, in `[tool.pytest.ini_options] addopts`, rather than being repeated in the Makefile, tox and CI. Any bare pytest run (make, tox, CI, IDE) is therefore safe by default. SR-003 deferred this addopts decision to SR-012. The `test-integration` target keeps its explicit marker selection, which overrides the default.
- P-02: There is no CI integration job, not even behind workflow_dispatch. Its inputs don't exist on runners, so the three tests would always skip ("data/raw directory not present") and report green, which is exactly the false-green failure SR-012 targets. The opt-in lane is `make test-integration` on a provisioned machine, and the README documents this.
- P-03: Coverage uses `branch = true` and `fail_under = 90` with `source = ["src"]`. This fast lane measured 91.02% branch coverage at plan time (93% statement-only). The 2 data/raw-dependent tests that skip on CI runners add no unique coverage: with them deselected, it was still 202 missed statements, 662 branches and 90 partial branches.
- P-04: Coverage is enforced once in CI (fast-lane, py3.12) and per version in tox. The matrix runs tests without coverage to stay lean.
- P-05: The doctest collection flag is dropped from the Makefile and tox. It collects zero items (292 tests with and without it). It is also the flag that, pointed at src/, would import `__main__` modules, and `compliance.workflows.__main__` runs the preprocessing CLI at import time and overwrites data/.
- P-06: `--strict-markers` joins addopts. It makes a typo'd marker an error instead of silently putting an integration test in the fast lane. At plan time the suite uses only `integration` and `parametrize`, and collection passes under strict markers.
- P-07: tox drops `--cov-config=pyproject.toml` (pyproject is auto-read, and the scratch-config run proved bare `--cov` honors it) and `--cov-report=xml` (no consumer: no codecov, no upload step).
- P-08: The workflow gains top-level `permissions: contents: read` (least privilege; no job writes anything).
- The orchestrator suggested an integration lane via workflow_dispatch. It was not adopted, per P-02.

Task classification (classify-tasks rules): Task 1 is simple and Task 2 is simple. This is concrete CI and config wiring with no production Python changes and no design fork, so no human pause is needed.

Coverage threshold location: pyproject `[tool.coverage.report]`, not config.yaml. It is tool configuration, not runtime application config, which matches where the existing ruff and mypy thresholds live (CLAUDE.md "Configuration").
