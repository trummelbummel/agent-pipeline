<objective>
SR-005 makes result publication transactional and run-scoped. Today `_persist_node` writes `analysis_result.json` and `predicted_answer.json` as two independent `write_text` calls, and preprocess writes `predicted_answer.json` as a third, with no shared generation identity. Three concrete failures follow: a crash or exception between the two analysis writes leaves a pair that looks valid but mixes generations; a failed rerun overwrites part of the last good result; and `make preprocess` on a tree that already holds analysis results can pair a fresh preprocess prediction with a stale `analysis_result.json`. Separately, the persist node mutates `document_metadata.json` **in the preprocessed input tree** to set `human_in_the_loop: true`, so an UNCERTAIN in one run is read back as a preprocess fact by the next run — HITL sticks across runs and analysis writes into its own inputs.

This plan introduces one run-scoped publication path: a `run_id` per run, a per-claim staging directory under `results_dir`, fsync, atomic renames, and a run manifest renamed **last** as the commit marker. A generation is valid only when the manifest and every artifact it names agree on the `run_id`; that is what makes a torn publication detectable instead of plausible. Consumers (the evaluator) refuse to score a claim whose prediction disagrees with its manifest. Analysis stops writing into the preprocessed tree and records HITL provenance in its own artifacts instead.

Locked decisions (from CONTEXT.md and `.gsd/steering-decisions-2026-09-29.md`):
- D-01: Per-claim temp directory under `results_dir`, then atomic promote of `analysis_result` + `predicted_answer` together.
- D-02: The last successful generation stays readable during a failed rerun.
- D-03: HITL sticky state clears per run — it is not carried across runs.

Planner discretion (flagged; report in SUMMARY):
- P-01: Staging lives at `results_dir/.staging/{run_id}/{claim_id}/` — a per-claim temp directory under `results_dir` (D-01), on the same filesystem as the destination so `os.replace` is atomic. The dot prefix keeps it out of every existing discovery filter (`_discover_claim_folders`, `discover_claim_folder_names`, and the API's `iterdir` list all require a `claim`-prefixed name), and keeping it outside the published claim directory means a crashed run leaves no debris where operators and the API read artifacts.
- P-02: `run_id` is `{UTC timestamp}-{uuid4 hex[:8]}` — lexically sortable for humans reading a results tree, collision-free for concurrent runs.
- P-03: The commit marker is `run_manifest.json` in the published claim directory, named on `PreprocessedArtifactNames` like every other artifact (CLAUDE.md: filenames are config-rooted, never hardcoded in source). It records `run_id`, `published_at`, `source`, and the artifact names it published. Validity of a generation = manifest `run_id` equals the `run_id` stamped in each named artifact. Torn states exist on disk; none of them satisfies that predicate, which is the structural answer to "interrupted writes cannot leave valid-looking partial pairs".
- P-04: A missing manifest means "pre-SR-005 tree" and is tolerated by readers, because `data/results/` already holds artifacts written before this change and `make evaluation` must keep scoring them. A manifest that is present and disagrees is an error. This is the only backward-compatibility affordance.
- P-05: Scope boundary, not a simplification: the **mirrored preprocessed artifacts** (description, answer, supporting docs, document_metadata, PNGs) keep their direct writes. `preprocessed_dir` holds deterministically re-derivable inputs, and the SR-005 "Done when" items are about scoring stale/mixed **results**. The preprocess-authored `predicted_answer` under `results_dir` **is** in scope and does become transactional, because that is the file the evaluator scores.
- P-06: No per-claim lock is added. Each run stages under its own `run_id` and commits by a single rename, so concurrent runs cannot interleave within one generation — the later commit simply wins. Cross-request locking and idempotency are SR-007's contract, and the constraint on this task is not to expand into it.
- P-07: HITL provenance replaces the in-place metadata mutation with `human_in_the_loop_source` (`preprocess_metadata` | `classifier_false` | `uncertain_decision` | `none`) plus `document_metadata_run_id` in `analysis_result.json`. Preprocess stamps `run_id` into `document_metadata.json`, so the analysis artifact names the input generation it read (backlog: "immutable + provenance"). Because analysis no longer writes that file and preprocess rewrites it from the bundle each run, HITL is recomputed per run (D-03).
- P-08: The failed-run manifest is written **only when a claim in the run failed** (`results_dir/.runs/{run_id}.json`), matching the backlog's "run manifest for failures". Successful runs leave only per-claim commit markers, so an API-driven run does not accumulate a file per request.

Behaviour changes to record in the SUMMARY (intended, not regressions to fix here):
- `document_metadata.json` in the preprocessed tree is no longer flagged by analysis. Operators who read HITL from that file now read `human_in_the_loop` / `human_in_the_loop_source` from `analysis_result.json` and `predicted_answer.json` (both already carry the flag).
- Every published claim directory under `results_dir` gains `run_manifest.json`, and both result artifacts gain a `run_id` key. `data/results/` is gitignored, so this does not touch version control.
- A claim whose prediction and manifest disagree is counted as incorrect by `make evaluation` instead of contributing a stale score.

Purpose: make a partially written or superseded result impossible to mistake for a current one (backlog risk "Stale / mixed-generation decisions"), and stop analysis from writing into its own inputs.
Output: one publication module, a run-scoped persist path, run-stamped preprocess predictions, immutable preprocessed metadata with provenance, an evaluator generation guard, tests over torn and failed runs, corrected docs, and SR-005 closed in the backlog.
</objective>

<publication_contract>
The contract every task implements (D-01, D-02, D-03).

**Publish (one claim, one run):**

1. `staging = results_dir/.staging/{run_id}/{claim_id}/` (P-01), created after `_validate_claim_dir_name(claim_id)`.
2. Write each artifact body into `staging`, `flush` + `os.fsync` each file, then fsync `staging`.
3. `os.replace` each artifact from `staging` into `results_dir/{claim_id}/`.
4. Write the manifest body into `staging`, fsync it, then `os.replace` it into the claim directory **last** — this is the commit point.
5. fsync the published claim directory; remove the now-empty staging directory, and the run directory when it holds nothing else.

**Validity predicate (readers):** a generation is current iff `run_manifest.json` exists, and for every artifact name it lists, that artifact's `run_id` equals the manifest `run_id`.

| On-disk state | Reads as |
|---------------|----------|
| manifest + both artifacts, all one run_id | valid current generation |
| crash before any rename | previous generation, intact and valid (D-02) |
| crash after one artifact rename, before manifest | previous manifest still committed; the newer artifact disagrees with it → mismatch, not a valid pair |
| crash after both artifacts, before manifest | previous manifest still committed; both artifacts disagree → mismatch |
| no manifest at all (pre-SR-005 tree) | legacy — readers tolerate and score as before (P-04) |
| manifest from a preprocess-only publication + older analysis_result | prediction valid; analysis_result superseded and detectable, still readable (D-02) |

**Run scope:** one `run_id` per `ClaimPipeline.run` / `PreprocessingPipeline.run`, or one per single-claim entry point (`analyze_claim`, `process_claim`, and therefore per API request). Failures in a run are recorded in `results_dir/.runs/{run_id}.json`, written only when at least one claim failed (P-08).

**Immutability:** analysis reads `document_metadata.json` and never writes it. HITL provenance goes into the published analysis artifacts (P-07), so no analysis outcome can be read back as a preprocess input fact in a later run (D-03).
</publication_contract>
